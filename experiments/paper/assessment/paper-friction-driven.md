# Assessment of the model records: paper-friction-driven

Task `friction-driven` (described task of the rotational motion under dry friction, driven by a voltage-controlled DC motor; states `theta` in rad and `omega` in rad/s, input `u` in V; a candidate consists of the two expressions `dtheta` and `domega`). The task has three formal requirements: R1 (`dtheta` = `omega`), R2 (`domega*theta <= 0` at `omega = 0` rad/s and `u = 0` V for `theta` in [-pi, pi] rad) and R3 (`domega` is increasing in `u`, not strictly, for `theta` in [-3.1416, 3.1416] rad, `omega` in [-23, 23] rad/s and `u` in [-10, 10] V). The five runs r01 to r05 were made on 2026-10-09 with the model `gpt-6.1-sol`. Marks proposed by an AI coding assistant (Claude) from the run records; checked against the evidence and confirmed without change by one of the authors. The items (a) to (e) are those of Section 5.6 of the manuscript: (a) interpretation of every term, (b) origin against the transcript, (c) parameter types against the estimation script, (d) reasons for the criterion, the method and the starting values, (e) limitations. The marking rule is the one of `experiments/paper/README.md`. `L<n>` is line n of `runs/<run>/transcript.jsonl`; a script or a result file is a file of `runs/<run>/workspace/`, and `script.py:n` is line n of that script. The harness, the software of ASPIRE, verifies the formal requirements; the assessment does not repeat that verification. It records only how the agent, the language model that produced the records, treated the requirements (list "Facts" of each run). No test result was read or used for a mark. A parameter that the optimizer returned at a bound is treated as `fitted`, as in the assessments of the other experiments; each such case is noted.

In all five runs the final parameter values were estimated on the training and the validation data together, after a comparison of structures by fits on the training data and simulation of the validation data. The runs r01 to r04 then compared the structures by cross-validation over the 16 trajectories of both files (r01, r03 and r04: one trajectory left out at a time; r02: three folds); r05 repeated the comparison without two training trajectories that it found to be the final samples of two validation trajectories. No run executed a symbolic-regression package (PySR, gplearn, PySINDy or another); the only package installed in each run was `numba`. Helper agents were started in r01, r02, r03 and r05 (one each, for an analysis of acceleration residuals; each stopped at its turn limit without a final text, and the main agent read the files it left); r04 started none. Every run searched the web, for bibliographic references and, in r01, for the documentation of the optimizer. All five runs evaluated R2 and R3 numerically at sampled points before the message `DONE`, and four records (r01, r02, r03, r05) also give an analytic argument; in no run did such a check lead to a change of a candidate. Each recommended model represents rest under static friction by a term that cancels the drive acceleration at zero velocity while this acceleration lies within the friction limits, and each expression `domega` is continuous in `omega` at `omega = 0`.

## r01: recommended model `HarmonicStiction`

Expressions:
`dtheta = omega`
`domega = (a*u - g*sin(theta)*(1 + h*cos(theta))) - b*omega - c*tanh(omega/v) - (1 - tanh(omega/v)**2)*Min(Max((a*u - g*sin(theta)*(1 + h*cos(theta))), -(c)), (c))`
